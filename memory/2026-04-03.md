## 1. 小红书运营工具需求文档

用户想要开发小红书运营相关的小工具，需求包括：
1. 自动监控小红书平台与「视频翻译」相关的搜索词，每日汇总到飞书多维表格
2. 根据监控到的关键词，抓取爆款帖子链接，每日汇总到飞书多维表格
3. 授权小红书登录后，自动抓取与搜索词相关的帖子链接和用户评论，并生成回复内容（人工审核后发送）

我提供了产品需求文档（PRD），将三个功能点整合为一个产品的三个阶段：
- **模块1：关键词监控器** - 每日自动搜索，输出到飞书多维表格
- **模块2：爆款抓取器** - 根据关键词抓取爆款帖子
- **模块3：智能互动助手** - 抓取评论、AI生成回复建议、人工审核

建议做成一个产品的3个阶段，MVP范围包括：最多5个关键词监控、按点赞数筛选前20条爆款、只抓取评论和生成建议（暂不支持自动发送）。

## 2. Workspace 文件浏览器

用户想直接访问 `/root/.openclaw/workspace/` 目录，我创建了一个静态文件浏览器网页。

**技术实现**：
- 纯前端实现：HTML + CSS + JavaScript
- GitHub 暗色主题设计
- 左侧文件树导航，右侧内容预览
- 文件数据打包在 data.js 中（压缩后约4KB）

**部署过程**：
1. 本地 Python 服务器版本（localhost:8080）
2. Vercel 静态部署版本
3. 创建独立分支 `vercel-deploy` 推送到 GitHub
4. 修复了 Vercel 误识别为 Python 项目的问题（移除了 generate.py）

**最终文件结构**（vercel-deploy 分支）：
```
├── index.html      # 主页面
├── style.css       # GitHub 暗色主题
├── app.js          # 交互逻辑
├── data.js         # 文件树数据
├── package.json    # Node 项目配置
└── vercel.json     # Vercel 配置
```

## 技术笔记

**Vercel 部署静态网站的关键**：
- 不要包含 Python 文件，否则 Vercel 会尝试安装 Python 依赖
- 使用 `package.json` 明确标记为 Node.js 项目
- 或使用空的 `vercel.json` 让 Vercel 自动识别为静态网站

**Git 操作**：
- 使用 `--orphan` 创建干净的分支，避免历史提交干扰
- 嵌套的 git 仓库需要使用 `git rm --cached` 移除
